# JD解码

输入：$ARGUMENTS

今天日期：!`date +%Y-%-m-%-d`

## 操作步骤

1. 如果用户输入的是文件路径，使用 `Read` 读取 JD 文件。如果是直接粘贴文本，使用用户提供的文本。
2. 如果用户提供了多份 JD（同一公司），先横向对比，再聚焦主 JD。
3. 使用 `Glob` 查找同岗位文件夹下已有的 `JD人才画像.md`（如果存在），对比是否有需要更新的内容。
4. 读取下列共享知识：
   - `共享知识/面试方法/01 面试官手册.md`
   - `共享知识/面试方法/02 人才选拔与面试技巧.md`
   - `共享知识/面试方法/03 JD解读方法.md`
   - `面试官/招聘配置/面试评价标准.md`
5. 读取同公司其他 JD 文件（如有），执行横向对比。
6. 输出到 `{主JD所在目录}/JD人才画像.md`。

## 输出结构

生成文档必须包含以下全部章节：

### 1. 岗位基本信息
- 岗位名称、部门、地点
- 岗位性质判断（独立主导 vs 协作参与、早期探索 vs 成熟优化）

### 2. 团队使命解读
- 团队使命原文
- 使命背后的产品方向判断
- 本岗位在使命中的角色定位

### 3. JD 能力模型

以表格形式输出每条 JD 要求的分析：

| JD 原文要求 | 能力维度 | 措辞强度 | 面试官验证重点 | 强信号 | 红旗信号 |
|------------|---------|---------|--------------|--------|---------|
| | | 必备/加分/灰色 | | | |

### 4. 核心考察方向（2-4 个）

将散列的 JD 要求归纳为 2-4 个核心方向。每个方向说明：
- 为什么这是核心方向
- 覆盖 JD 中哪几条
- 面试官会从哪里切入

### 5. 加分项分析
- 哪些是"拉开差距"的进攻点
- 哪些是公司文化信号
- 哪些可以忽略

### 6. 岗位信号

基于 JD 措辞推断：
- 团队阶段与规模
- 角色独立性
- 面试风格倾向
- 本岗位"不负责什么"（从同公司其他 JD 的分工推断）

### 7. （如有同公司多 JD）横向对比

- 与同公司其他岗位 JD 的关键差异
- 共享部分（同样的产品/团队）
- 分工边界（你做什么 vs 别人做什么）

## 约束

- 不凭"我知道"写内容。每条判断必须锚定到 JD 原文的措辞或共享知识里的方法论。
- 如果 JD 中出现具体产品名、技术名词、公司名等事实性信息，使用 `WebSearch` 校验当前状态，不要基于过期知识。
- 横向对比时不越权——不分析你要投的岗位"更好"还是其他岗位"更好"，只分析"这个岗位做什么，那个岗位做什么"。
- 产物里不包含任何对候选人个人情况的判断（这个阶段只看 JD，不看人）。
