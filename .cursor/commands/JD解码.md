# JD解码

基于面试方法论和 JD 解读方法，反推 JD 背后的人才画像。支持同公司多份 JD 横向对比。输出到岗位文件夹下的 `JD人才画像.md`。

> 本阶段只看 JD，不看候选人个人信息。不判断候选人是否具备某项能力，只判断 JD 在找什么能力。

---

## 参数解析

从用户调用命令时附带的自然语言中解析：

- **主 JD**：粘贴文本，或 `@` 引用 JD 文件路径
- **岗位文件夹**（可选）：如 `候选人/幻方-DeepSeek/`；未指定时，输出到主 JD 所在目录
- **同公司其他 JD**（可选）：`@` 引用多份文件，用于横向对比

推荐调用方式：

```text
/JD解码 @候选人/幻方-DeepSeek/JD.md
/JD解码 @候选人/幻方-DeepSeek/JD-A.md @候选人/幻方-DeepSeek/JD-B.md
```

文件名日期使用当前日期，格式为 `{YYYY-M-D}`。如上下文中没有可靠日期，使用 `Shell` 执行 `date +%Y-%-m-%-d` 获取。

## 文件命名

`{岗位路径}/JD人才画像.md`

---

## 操作步骤

1. 若用户使用 `@` 引用文件，以引用内容为准；否则解析用户粘贴的 JD 文本或给出的文件路径。
2. 若用户提供多份 JD（同一公司），先横向对比，再聚焦主 JD。
3. 使用 `Glob` 查找同岗位文件夹下已有的 `JD人才画像.md`（如存在，对比是否需要更新）。
4. 使用 `ReadFile` 读取下列共享知识：
   - `共享知识/面试方法/01 面试官手册.md`
   - `共享知识/面试方法/02 人才选拔与面试技巧.md`
   - `共享知识/面试方法/03 JD解读方法.md`
   - `面试官/招聘配置/面试评价标准.md`
5. 读取同公司其他 JD 文件（如有），执行横向对比。
6. 使用文件编辑工具创建或更新 `{主 JD 所在目录}/JD人才画像.md`。

## 输出结构（严格遵循）

生成文档必须包含以下全部章节：

### 1. 岗位基本信息

- 岗位名称、部门、地点
- 岗位性质判断（独立主导 vs 协作参与、早期探索 vs 成熟优化）

### 2. 团队使命解读

- 团队使命原文
- 使命背后的产品方向判断
- 本岗位在使命中的角色定位

### 3. JD 能力模型

以表格形式输出每条 JD 要求的分析：

| JD 原文要求 | 能力维度 | 措辞强度 | 面试官验证重点 | 强信号 | 红旗信号 |
|------------|---------|---------|--------------|--------|---------|
| | | 必备/加分/灰色 | | | |

### 4. 核心考察方向（2-4 个）

将散列的 JD 要求归纳为 2-4 个核心方向。每个方向说明：

- 为什么这是核心方向
- 覆盖 JD 中哪几条
- 面试官会从哪里切入

### 5. 加分项分析

- 哪些是「拉开差距」的进攻点
- 哪些是公司文化信号
- 哪些可以忽略

### 6. 岗位信号

基于 JD 措辞推断：

- 团队阶段与规模
- 角色独立性
- 面试风格倾向
- 本岗位「不负责什么」（从同公司其他 JD 的分工推断）

### 7. （如有同公司多 JD）横向对比

- 与同公司其他岗位 JD 的关键差异
- 共享部分（同样的产品/团队）
- 分工边界（你做什么 vs 别人做什么）

---

## 约束

- 不凭「我知道」写内容。每条判断必须锚定到 JD 原文的措辞或共享知识里的方法论。
- 若 JD 中出现具体产品名、技术名词、公司名等事实性信息，使用 `WebSearch` 校验当前状态，不要基于过期知识。
- 横向对比时不越权——不分析你要投的岗位「更好」还是其他岗位「更好」，只分析「这个岗位做什么，那个岗位做什么」。
- 产物里不包含任何对候选人个人情况的判断。
