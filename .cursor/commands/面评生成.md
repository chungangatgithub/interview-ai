# 面评生成

基于候选人简历、问答文档和面试语音转文字原始记录，生成结构化面试评价报告，保存到 `面试官/面试报告/` 目录。

> 本命令合并“面试记录整理”和“面评生成”两个内部步骤。对用户只暴露一个命令，但执行时必须先从原始转写中抽取证据，再基于证据写面评。禁止直接从简历或问答计划推断候选人表现。

---

## 参数解析

从用户调用命令时附带的自然语言中解析候选人姓名、简历文件名、问答文件名和面试记录文件名。若用户使用 `@` 引用具体文件，以引用内容为准。

推荐调用方式：

```text
/面评生成 丛思羽 @面试记录/2026-5-15-丛思羽-原始转写.md
```

文件名日期和报告日期使用当前日期。若上下文中没有可靠日期，使用 `Shell` 执行 `date +%Y-%-m-%-d` 获取文件名日期，并转换为 `{YYYY 年 M 月 D 日}` 写入报告。

## 文件命名

`面试官/面试报告/{YYYY-M-D}-{姓名}-面试评价报告.md`

---

## 操作步骤

1. 使用 `Glob` 定位候选人文件：
   - 简历：`面试官/候选人简历/*{姓名}*.md`
   - 问答：优先匹配 `面试官/面试问答/*{姓名}*.md`
   - 面试记录：优先使用用户 `@` 引用；否则在 `面试记录/`、`interview/`、`records/` 下搜索 `*{姓名}*.md`
2. 使用 `ReadFile` 读取上述文件，以及下方“参考资料”列表。
3. 执行「内部步骤一：原始转写整理与证据抽取」。
4. 对照 `面试官/招聘配置/岗位人才画像.md` 将证据映射到必备项、加分项、强风险、专业能力和素质能力。
5. 执行「内部步骤二：基于证据生成正式面评」。
6. 使用文件编辑工具创建 `面试官/面试报告/{YYYY-M-D}-{姓名}-面试评价报告.md`。

## 证据优先级

1. **最高优先级**：面试语音转文字原始记录中的候选人原话和具体行为事件。
2. **辅助证据**：面试官在原始记录中的追问、澄清和候选人当场确认。
3. **评价标准**：`面试官/招聘配置/岗位人才画像.md`、`面试官/招聘配置/面试评价标准.md`。
4. **背景资料**：简历、问答文档、岗位信息。

禁止行为：

- 禁止把简历内容当作面试表现。
- 禁止把问答文档中的“期望答案”当作候选人回答。
- 禁止把面试官说的话当作候选人观点。
- 禁止对原始记录中未出现的维度强行评分。
- 没有证据的维度必须写“本轮未充分验证”。

## 内部步骤一：原始转写整理与证据抽取

先从原始转写中整理结构化证据，再写面评。报告中必须保留“结构化证据摘要”章节，方便复核。

### 1. 区分说话人

- 尽量区分面试官发言和候选人发言。
- 若转写未明确说话人，根据问答上下文谨慎判断；不确定时标注“说话人不确定”。
- 面试官的引导、解释、提示不得作为候选人能力证据。

### 2. 对齐问答文档

将原始转写尽量对齐到问答文档中的问题：

- 哪些问题被完整询问。
- 哪些问题被跳过。
- 哪些问题发生了偏离。
- 哪些候选人回答与简历疑点或岗位核心能力相关。

### 3. 提取 STAR / BEI 证据

对候选人每个关键回答提取：

- Situation（情境）：当时背景、参与方、挑战。
- Task（任务）：候选人个人目标、职责、成功标准。
- Action（行动）：候选人本人采取的具体动作。
- Result（结果）：量化结果、业务影响、复盘和复用。

如果要素缺失，明确标注：

- “缺 S：未说明背景难度”
- “缺 T：未说明个人目标”
- “缺 A：行动描述笼统”
- “缺 R：结果无量化或归因不清”

### 4. 提取关键证据

必须提取并归类：

- 候选人关键原话或近似原话
- 项目角色边界
- 成果数字及口径
- 决策逻辑
- 协作冲突
- 学习与复盘
- 强信号
- 风险点
- 回避、答非所问、无法说明的内容
- 需要下一轮继续验证的点

### 5. 对齐岗位人才画像

将证据映射到 `面试官/招聘配置/岗位人才画像.md`：

- 必备项：哪些已验证，哪些未充分验证，哪些存在不足。
- 加分项：哪些有证据支持，不能用加分项替代必备项。
- 强风险 / 一票否决：是否出现证据，若出现必须单独标注。
- 专业能力：AI 产品认知、数据分析智能体场景理解、0-1 落地、评测治理、B 端交付等。
- 素质能力：学习敏锐度、逻辑思维、主动性、协作、抗压复盘、真诚可信等。

## 内部步骤二：正式面评生成规则

正式面评只能基于“结构化证据摘要”生成。

### 评分规则

- 评分范围：1-5 分（整数），及格线 3.0 分。
- 平均分保留一位小数。
- 对标候选人的目标岗位、`面试官/招聘配置/岗位人才画像.md` 与本轮面试官定位。
- 画像中的必备项如果本轮未验证，必须写入“本轮未充分验证”或“下一轮建议验证”。
- 加分项不能替代必备项；候选人有亮点但必备项不足时，应明确风险。
- 本轮未充分验证的维度，不强行评分；如模板必须填写，评分说明写“本轮证据不足，建议下一轮验证”。
- 推荐意见可使用：强烈推荐、推荐、待定、不推荐、建议加面。

### 面试官定位约束

根据 `面试官/招聘配置/面试官信息.md`，本轮默认是 AI Coding / AI 产品方向专业面试官。报告应体现：

- 本轮负责专业能力、项目真实性、AI 产品/AI Coding 匹配度和基础素质观察。
- 不默认负责最终录用决策、薪资、全面文化终审和最终职级定级。
- 如使用“推荐/不推荐”，应表述为“本轮建议”，不是最终录用决定。

### 内容撰写规则

1. **事实与推断分离**：事实引用候选人回答；推断说明依据。
2. **避免空泛评价**：不用“沟通能力好”“技术不错”这类无证据描述。
3. **每个优势/风险都要有证据**：至少引用一个回答摘要、行为事件或关键原话。
4. **保留下一轮建议**：明确哪些能力本轮未验证，建议谁继续验证。
5. **敏感边界**：不讨论薪资，不泄露公司机密，不做与岗位无关的评价。
