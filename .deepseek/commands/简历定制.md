# 简历定制

输入：用户调用时指定对标表文件路径。

当前日期：使用 `bash` 执行 `date +%Y-%-m-%-d` 获取。

## 操作步骤

1. 使用 `read` 读取对标表文件。
2. 使用 `read` 读取 `面试官/招聘配置/岗位人才画像.md` 作为简历组织方式的参考。
3. 只基于对标表「我的证据」列中已填写的经历组织简历内容。
4. 使用 `write` 输出到 `{对标表所在目录}/定制简历.md`。

## 输出结构

### 定制简历

简历分为以下几个板块，按 JD 重要度排序：

1. **个人信息**：姓名、联系方式、目标岗位
2. **核心能力摘要**：3-5 条，每条 1 句话，直接锚定 JD 的核心能力项。不写「具备XX能力」，而是用经历事实说话（「曾主导XX产品从0到1，覆盖XX场景，实现XX指标变化」）
3. **工作经历**：每段经历包含公司/角色/时间 + 3-5 个要点。每个要点都是 STAR 浓缩版。JD 最看重的经历放最前面。与 JD 无关的职责一笔带过或不写
4. **项目经历**（可选）：如果对标表中某个项目能强证明某条 JD 能力，单独展开
5. **教育背景**
6. **其他**：与 JD 加分项相关的额外信息

## 组织原则

- **锚定**：简历里每条经历都和 JD 能力项有映射关系（不写这句映射在简历正文里，但你能说清楚「为什么写这段」）
- **排序**：JD 必备项对应的经历优先排列，加分项对应经历靠后
- **删减**：与 JD 无关的经历一律精简为一句话或不写
- **诚实**：不编造经历、不虚增数字。对标表里没有证据的 JD 能力项，简历不主动提，但也不撒谎说「我有这个经验」

## 约束

- 不添加对标表中没有的经历
- 不夸大对标表中的数字和职责
- 如果对标表有多条 JD 能力项标记为「无直接证据」，在简历末尾提醒候选人：这些能力项简历未覆盖，面试官可能会问，建议提前准备回应策略（见面试准备册）
