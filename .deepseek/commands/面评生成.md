# 面评生成

输入：用户调用时指定候选人姓名，可选指定面试记录原始转写文件路径。

当前日期：使用 `bash` 执行 `date +%Y-%-m-%-d` 获取。

> 本命令合并「面试记录整理」和「面评生成」两个内部步骤。对用户只暴露一个命令，但执行时必须先从原始转写中抽取证据，再基于证据写面评。禁止直接从简历或问答计划推断候选人表现。

## 操作步骤

1. 使用 `find` 定位候选人文件：
   - 简历：`面试官/候选人简历/*{姓名}*.md`
   - 问答：`面试官/面试问答/*{姓名}*.md`
   - 面试记录：优先使用用户指定的路径；否则在 `面试记录/`、`interview/`、`records/` 下搜索 `*{姓名}*.md`
2. 使用 `read` 读取上述文件和参考资料，尤其必须读取 `面试官/招聘配置/岗位人才画像.md`。
3. 执行内部步骤一：原始转写整理与证据抽取。
4. 对照 `面试官/招聘配置/岗位人才画像.md` 将证据映射到必备项、加分项、强风险、专业能力和素质能力。
5. 执行内部步骤二：基于证据生成正式面评。
6. 使用 `write` 输出到 `面试官/面试报告/{日期}-{姓名}-面试评价报告.md`。

## 必读资料

- `面试官/招聘配置/岗位信息.md`
- `面试官/招聘配置/岗位人才画像.md`
- `面试官/招聘配置/面试官信息.md`
- `面试官/招聘配置/面试评价标准.md`
- `共享知识/面试方法/01 面试官手册.md`
- `共享知识/面试方法/02 人才选拔与面试技巧.md`
- 候选人简历（`面试官/候选人简历/`）
- 当次问答文档（`面试官/面试问答/`）
- 面试语音转文字原始记录（用户提供）

## 证据优先级

1. 最高优先级：面试语音转文字原始记录中的候选人原话和具体行为事件。
2. 辅助证据：面试官在原始记录中的追问、澄清和候选人当场确认。
3. 评价标准：`面试官/招聘配置/岗位人才画像.md`、`面试官/招聘配置/面试评价标准.md`。
4. 背景资料：简历、问答文档、岗位信息。

禁止：

- 把简历内容当作面试表现。
- 把问答文档中的「期望答案」当作候选人回答。
- 把面试官说的话当作候选人观点。
- 对原始记录中未出现的维度强行评分。
- 没有证据的维度必须写「本轮未充分验证」。

## 内部步骤一：原始转写整理与证据抽取

必须先整理结构化证据，并在报告中保留「结构化证据摘要」章节。

### 区分说话人

- 尽量区分面试官发言和候选人发言。
- 若转写未明确说话人，根据问答上下文谨慎判断；不确定时标注「说话人不确定」。
- 面试官的引导、解释、提示不得作为候选人能力证据。

### 对齐问答文档

整理：

- 哪些问题被完整询问。
- 哪些问题被跳过。
- 哪些问题发生了偏离。
- 哪些候选人回答与简历疑点或岗位核心能力相关。

### 提取 STAR / BEI 证据

对关键回答提取：

- Situation：背景、参与方、挑战。
- Task：个人目标、职责、成功标准。
- Action：本人采取的具体动作。
- Result：量化结果、业务影响、复盘和复用。

如果要素缺失，明确标注：

- 缺 S：未说明背景难度。
- 缺 T：未说明个人目标。
- 缺 A：行动描述笼统。
- 缺 R：结果无量化或归因不清。

### 提取关键证据

必须提取：

- 候选人关键原话或近似原话
- 项目角色边界
- 成果数字及口径
- 决策逻辑
- 协作冲突
- 学习与复盘
- 强信号
- 风险点
- 回避、答非所问、无法说明的内容
- 需要下一轮继续验证的点

### 对齐岗位人才画像

将证据映射到 `面试官/招聘配置/岗位人才画像.md`：

- 必备项：哪些已验证，哪些未充分验证，哪些存在不足。
- 加分项：哪些有证据支持，不能用加分项替代必备项。
- 强风险 / 一票否决：是否出现证据，若出现必须单独标注。
- 专业能力：AI 产品认知、数据分析智能体场景理解、0-1 落地、评测治理、B 端交付等。
- 素质能力：学习敏锐度、逻辑思维、主动性、协作、抗压复盘、真诚可信等。

## 内部步骤二：正式面评生成规则

正式面评只能基于结构化证据摘要生成。

### 评分规则

- 评分范围：1-5 分整数，及格线 3.0 分。
- 平均分保留一位小数。
- 对标候选人的目标岗位、`面试官/招聘配置/岗位人才画像.md` 与本轮面试官定位。
- 画像中的必备项如果本轮未验证，必须写入「本轮未充分验证」或「下一轮建议验证」。
- 加分项不能替代必备项；候选人有亮点但必备项不足时，应明确风险。
- 本轮未充分验证的维度，不强行评分；如模板必须填写，说明写「本轮证据不足，建议下一轮验证」。
- 推荐意见可使用：强烈推荐、推荐、待定、不推荐、建议加面。

### 面试官定位约束

根据 `面试官/招聘配置/面试官信息.md`，本轮默认是 AI Coding / AI 产品方向专业面试官：

- 本轮负责专业能力、项目真实性、AI 产品/AI Coding 匹配度和基础素质观察。
- 不默认负责最终录用决策、薪资、全面文化终审和最终职级定级。
- 如使用「推荐/不推荐」，应表述为「本轮建议」，不是最终录用决定。

## 输出结构

生成文档必须包含：

1. 标题：`# {姓名} - 面试评价报告`
2. 面试岗位、面试日期、面试官定位、报告性质、本轮建议
3. 结构化证据摘要：
   - 面试问题覆盖情况
   - 关键行为证据
   - 关键数字与口径
   - 强信号与风险点
   - 本轮未充分验证
4. AI 思维模式及深度评估
5. 专业能力评价
6. 通用能力与潜力评价
7. 综合评价
8. 下一轮建议验证点
9. 报告生成日期
