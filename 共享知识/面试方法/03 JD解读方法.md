# JD 解读方法

## JD 信息分层

拿到一份 JD，先分层：

1. **团队使命/产品使命** — 最高信号。如果多份 JD 共享同一段使命（如 Harness PM 和 Harness 研发），说明这是同一产品、同一团队。
2. **主要职责** — 日常工作流。看动词：规划/设计/开发/维护/协同/主导。动词告诉你这个岗位是思考型还是执行型、是独立决策还是配合他人。
3. **任职要求** — 硬性门槛。看措辞强度："必须/熟练掌握" vs "优先/了解" vs "加分项"。
4. **加分项** — 团队想要但可能找不到完全匹配的人。也是你的差异化进攻点。

## 措辞信号

| 措辞 | 实际含义 |
|------|---------|
| "参与" | 不是主导，有上级带 |
| "负责/主导" | 独立决策，你说了算 |
| "与XX紧密协作" | 跨角色沟通是核心工作方式 |
| "深度参与/深度理解" | 不是用过就行，要有体系化认知 |
| "有品味有判断力" | 没有标准答案，需要主观审美+经验 |
| "特别优秀可放宽" | 不是死要求，但你的其他项得特别强 |
| "加分项" | 不是必选项，但决定了筛简历时的排序 |

## 必备项 vs 加分项 的判断

JD 不一定明写"必备"和"加分"，通过措辞判断：

- **必备**：出现在"任职要求"中且措辞强（"具备""熟练""熟悉"），面试中必被验证
- **加分**：明确标注"加分项"，或措辞弱（"优先""有兴趣"）
- **灰色地带**：出现在"任职要求"但措辞软（"了解""有相关经验者优先"）→ 面试官可能问但不会卡死

## 同公司多 JD 横向对比

- 共享使命 = 同产品/同团队 → PM 和研发的分工差异 = 这个岗位"不负责什么"
- JD 措辞在公司内部的差异：同一个概念（如"Agent 机制"）在不同岗位 JD 中出现的深度不同 → 本岗位对这项能力的具体层级
- 加分项对比：有的加分项是全员通用的（如"开源贡献"），有的是岗位特有的 → 区分哪些是公司文化信号、哪些是岗位独特信号

## 从 JD 反推面试官

- 哪几条要求出现了"深度/体系化/品味" → 这些是核心考察项，面试官会深挖
- 哪几条措辞弱、像凑数的 → 面试官可能一笔带过
- JD 是措辞克制型（写得简单）还是堆料型（列了一堆技术名词）→ 面试风格倾向
- 同一团队多个岗位的 JD → 你的面试官可能不是同一个人，但他们的评价标准共享同一套框架

## 岗位信号判断

- 独立 vs 螺丝钉：看职责描述中是"主导/定义"还是"参与/协助"
- 团队阶段：看职责是否包含架构选型、0-1 探索、内部落地 → 早期团队。只提优化、迭代、规模化 → 成熟团队
- PM/研发关系：看是否提到"与XX紧密协作"以及双方 JD 的重叠程度
