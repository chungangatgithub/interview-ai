# 专项-信息安全

> 本文档基于行业标准（CISSP CBK、CISP、ISO 27001、GB/T 国标）和主流安全企业（奇安信、深信服、启明星辰、安芯网盾、亚信安全等）的实际招聘 JD 整理。

## 行业知识体系基准

信息安全领域的知识体系以 CISSP CBK（八大知识域）为全球行业基准。国内对应认证为 CISP，标准体系以 GB/T 22080（等同采用 ISO/IEC 27001）为核心。

### CISSP CBK 八大知识域（2024/2025 版）

| 域 | 中文名称 | 核心内容 |
|----|---------|---------|
| **Domain 1** | 安全与风险管理 | 安全治理、合规、风险框架、BCP、职业道德 |
| **Domain 2** | 资产安全 | 资产分类分级、数据生命周期、隐私保护 |
| **Domain 3** | 安全架构与工程 | 安全模型、密码学、PKI、物理安全、零信任、SASE |
| **Domain 4** | 通信与网络安全 | 网络协议安全、安全通道、微隔离、SDN、无线安全 |
| **Domain 5** | 身份与访问管理(IAM) | AAA、多因素认证、无密码认证、联邦身份、零信任访问 |
| **Domain 6** | 安全评估与测试 | 渗透测试、漏洞评估、安全审计、红蓝紫队 |
| **Domain 7** | 安全运营 | 事件响应、灾难恢复、日志监控、补丁管理、SOAR/MSS |
| **Domain 8** | 软件开发安全 | SDLC安全、DevSecOps、安全编码、SAST/DAST/IAST |

2024/2025 新增：AI 安全攻击与防御、量子密钥分发、SASE、无密码认证、SBOM（软件物料清单）。

### 中国标准体系

- **GB/T 22080-2025**（等同 ISO/IEC 27001:2022）：信息安全管理体系要求（2026.1.1 实施）
- **GB/T 45940-2025**：网络安全运维实施指南（2026.2.1 实施）
- **GB/T 45958-2025**：人工智能计算平台安全框架
- **GB/T 31722-2025**：信息安全风险管理指导
- 标准命名统一从"信息技术 安全技术"更名为"网络安全技术"

## CIA 三要素

- **机密性 (Confidentiality)**：确保数据只能被授权方访问。手段：加密、访问控制、身份认证。
- **完整性 (Integrity)**：确保数据未被未授权篡改。手段：哈希校验、数字签名、审计日志。
- **可用性 (Availability)**：确保授权用户能在需要时访问系统。手段：冗余、负载均衡、DDoS 防护。

## 常见攻击类型

| 攻击类型 | 原理 | 防护思路 |
|---------|------|---------|
| SQL 注入 | 用户输入被拼接进 SQL 语句执行 | 参数化查询、ORM、输入校验 |
| XSS (跨站脚本) | 恶意脚本注入页面在用户浏览器执行 | 输出编码、CSP、输入过滤 |
| CSRF (跨站请求伪造) | 诱导用户执行非本意操作 | CSRF Token、SameSite Cookie |
| SSRF (服务端请求伪造) | 诱导服务器发起非预期请求 | URL 白名单、内网隔离 |
| 命令注入 | 用户输入被拼接进系统命令执行 | 参数化、白名单校验、沙箱隔离 |
| DDoS (分布式拒绝服务) | 消耗目标资源使其不可用 | 流量清洗、CDN、速率限制 |
| 供应链攻击 | 通过第三方组件/依赖植入恶意代码 | SBOM、依赖审计、签名验证 |

## 认证与授权

- **认证 (Authentication)**：确认你是谁。方式：密码、MFA（多因素）、OAuth、SSO、Passkey（无密码）。
- **授权 (Authorization)**：确认你能做什么。模型：RBAC（基于角色）、ABAC（基于属性）、PBAC（基于策略）。
- **最小权限原则 (Least Privilege)**：每个主体只拥有完成其任务所必需的最小权限。

## 安全开发

- **SDL (安全开发生命周期)**：需求分析 → 威胁建模 → 安全设计 → 安全编码 → 安全测试 → 安全部署 → 安全运维
- **DevSecOps**：将安全嵌入 CI/CD 流水线，左移安全测试
- **威胁建模**：STRIDE（Spoofing, Tampering, Repudiation, Info Disclosure, DoS, Elevation of Privilege）
- **应用安全测试**：SAST（静态）、DAST（动态）、IAST（交互式）
- **供应链安全**：SBOM（软件物料清单）管理、依赖扫描、开源组件漏洞跟踪

## 数据安全

- **数据分类分级**：公开、内部、机密、绝密
- **数据生命周期**：创建 → 存储 → 使用 → 共享 → 归档 → 销毁
- **加密体系**：传输加密(TLS)、存储加密(AES)、端到端加密(E2EE)
- **隐私保护技术**：数据脱敏、差分隐私、k-匿名性、同态加密
- **主要隐私法规**：GDPR（欧盟）、PIPL/个人信息保护法（中国）、CCPA（加州）

## 安全运营

- **SOC (安全运营中心)**：7×24 安全监测
- **SIEM**：安全信息与事件管理，日志汇聚与关联分析
- **SOAR**：安全编排自动化与响应
- **事件响应流程**：准备 → 检测分析 → 遏制 → 根除 → 恢复 → 总结复盘
- **漏洞管理**：资产发现 → 漏洞扫描 → 风险评估 → 修复优先级 → 验证

## 等级保护（等保）

中国法定的信息安全等级保护制度，基于《网络安全法》第二十一条。安全岗位 JD 高频要求。

**五个等级**：
- **一级（自主保护）**：信息系统受到破坏后，对公民、法人合法权益造成损害
- **二级（指导保护）**：对社会秩序和公共利益造成损害（大部分企业系统在这一级）
- **三级（监督保护）**：对国家安全造成损害（金融、政府等关键系统）
- **四级（强制保护）**：对国家安全造成严重损害
- **五级（专控保护）**：对国家安全造成特别严重损害

**等保 2.0 五大维度**：物理安全、网络安全、主机安全、应用安全、数据安全与备份恢复。新增云计算、移动互联、物联网、工业控制、大数据五大扩展安全要求。

## 风险评估

- **风险评估流程**：资产识别 → 威胁识别 → 脆弱性识别 → 风险计算 → 风险处置
- **风险计算**：R（风险）= A（资产价值）× T（威胁频率）× V（脆弱性严重程度）
- **风险处置方式**：降低（通过安全措施减少风险）、转移（购买保险/外包）、规避（停止活动）、接受（风险在可接受范围内）
- **常见方法论**：ISO 27005（信息安全风险管理）、NIST SP 800-30（风险评估指南）、GB/T 20984（信息安全风险评估规范）

## 渗透测试简述

- **定义**：模拟真实攻击者行为，对系统进行授权的安全性测试，发现可被利用的漏洞。
- **流程**：信息收集 → 漏洞扫描 → 漏洞利用 → 权限提升 → 横向移动 → 清除痕迹 → 报告
- **类型**：黑盒（无内部信息）、白盒（提供内部信息）、灰盒（部分信息）
- **红蓝紫队**：红队（攻击方）、蓝队（防御方）、紫队（协调并促进双方协作）
- **与产品经理的关系**：不需要动手执行渗透测试，但需理解测试结论、能评估漏洞严重性、能据此制定产品安全需求优先级

## 安全沙箱（安全产品形态）

与 Agent 架构中的 sandbox 执行环境不同，安全领域的沙箱是**恶意代码分析产品**：

- **功能**：在隔离环境中运行可疑文件/URL，观察其行为（文件修改、网络连接、注册表变更等），判断是否为恶意软件
- **检测方式**：静态分析（不执行，分析代码结构）+ 动态分析（在沙箱中执行，观察行为）
- **典型场景**：邮件附件检测、可疑 URL 分析、APT 攻击样本分析
- **相关产品**：FireEye、Cuckoo Sandbox（开源）、各类威胁情报平台内置的沙箱模块

## 安全检测引擎

- **特征检测 (Signature-based)**：基于已知恶意代码的特征库匹配。优点：精准、误报低。缺点：无法检测新型/变种攻击。
- **行为检测 (Behavior-based)**：监控程序运行时的行为模式（如修改注册表、注入进程）。优点：可检测未知威胁。缺点：误报较高。
- **启发式分析 (Heuristic Analysis)**：基于规则和经验的模式匹配，判断程序意图。介于特征和行为之间。
- **机器学习检测**：使用 ML 模型识别恶意行为模式。2025-2026年趋势：大模型驱动的智能检测（LLM 分析告警、自动化研判）。
- **威胁情报联动**：结合全球威胁情报源实时更新检测能力。
