# AI Coding 产品

---

## 适用范围

用于 AI Coding 产品经理、Coding Agent 产品经理、研发工具产品经理、编辑器/IDE 产品经理等方向面试。

---

## AI Coding 产品形态

| 形态 | 用户价值 | 产品关键点 |
|------|----------|------------|
| 代码补全 | 降低重复编码成本 | 低打扰、低延迟、上下文准确 |
| Chat / 问答 | 解释代码、报错、框架用法 | 需要代码上下文和引用来源 |
| Inline Edit / 多文件编辑 | 根据自然语言修改代码 | Diff 审阅、最小改动、可撤回 |
| Coding Agent | 搜索代码、改代码、跑测试、循环修复 | 工具调用、验证闭环、权限和沙箱 |
| 后台任务 / Issue to PR | 长任务自动执行 | 审计、检查点、失败恢复、人工接管 |

---

## 研发用户工作流

AI Coding 产品经理需要理解研发用户不是只要“生成代码”，而是要完成任务：

1. 理解需求或 issue
2. 找到相关代码和上下文
3. 设计修改方案
4. 编写或修改代码
5. 生成/补充测试
6. 运行测试和调试
7. 审阅 Diff
8. 提交 PR 或交付变更

产品设计要围绕任务完成率、可信度、可审阅和可验证，而不只看生成速度。

---

## 常见指标

| 指标 | 含义 | 注意事项 |
|------|------|----------|
| 接受率 | 用户接受 AI 建议的比例 | 接受不等于最终有价值 |
| 代码生成率 | AI 生成代码占新增代码的比例 | 必须说明分子分母、是否排除模板代码 |
| 返工率 | AI 生成后被大幅修改或回滚的比例 | 是质量和信任的重要指标 |
| 测试通过率 | AI 修改后测试通过情况 | 不能只看单测，也要看构建和回归 |
| 任务完成时长 | 从需求到可交付变更的耗时 | 更接近真实提效 |
| 用户接管率 | 用户中断或手动改写 Agent 结果的比例 | 可反映可控性和信任问题 |

---

## 产品设计强信号

- 能从研发任务链路讲 AI Coding，而不是只讲补全或生成代码
- 能说明上下文、工具调用、验证、审阅和回滚对用户信任的重要性
- 能区分“生成率”与“真实提效”
- 能设计企业内部场景的权限、私有代码保护、日志审计和高风险操作确认
- 能说明什么时候不适合全自动 Agent，而应保留 Copilot 式用户控制

## 面试追问建议

1. 你负责的 AI Coding 产品服务哪类研发？他们最痛的环节是什么？
2. 如果 AI 生成代码通过测试但研发不敢用，产品上如何解决？
3. “代码生成率 70%”如何定义？为什么不等于提效 70%？
4. 企业内部 Coding Agent 如何处理敏感代码和危险命令？
5. 什么时候适合做强编排，什么时候适合让 Agent 自主探索？

## 评分锚点

| 分数 | 表现 |
|------|------|
| 5 分 | 深刻理解研发工作流和 AI Coding 产品机制，能设计可信、可控、可验证的产品闭环 |
| 4 分 | 有 AI Coding 项目经验，能讲清指标、用户体验和主要风险 |
| 3 分 | 理解 AI Coding 基本形态，但对研发信任和验证闭环理解一般 |
| 2 分 | 只关注代码生成，缺少任务完成和质量视角 |
| 1 分 | 对研发用户和 AI Coding 产品缺少真实理解 |
