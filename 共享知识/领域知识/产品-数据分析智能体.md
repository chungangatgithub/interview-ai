# 数据分析智能体产品

---

## 适用范围

用于数据分析 Agent、BI 智能助手、游戏运营分析 Agent、业务复盘 Agent 等 AI 产品经理方向面试。

---

## 数据分析工作流

数据分析智能体不应被简化为自然语言查数。完整工作流通常包括：

1. 业务问题定义：用户想解决什么业务决策问题。
2. 指标拆解：北极星指标、过程指标、护栏指标、分群维度。
3. 数据获取：取数、权限、口径、时间窗口、对照组。
4. 分析与归因：异常识别、趋势分析、分群对比、假设生成。
5. 结论表达：事实、推断、建议分层输出。
6. 人工确认：关键口径、敏感结论、高风险建议必须由人确认。
7. 复盘沉淀：用户反馈、bad case、评测集、知识库更新。

## 典型产品场景

| 场景 | 用户 | 产品价值 | 风险点 |
|------|------|----------|--------|
| 活动效果复盘 | 运营、策划 | 快速生成分析框架和复盘草稿 | 指标口径错误导致误判 |
| 异常波动分析 | 运营、分析师 | 提醒异常并生成候选原因 | 把相关性误当因果 |
| 指标解释 | 新人、业务方 | 降低理解指标和报表门槛 | 解释不符合公司内部口径 |
| 玩家分群洞察 | 策划、运营 | 找到不同用户行为差异 | 分群过度解释或样本不足 |
| 分析计划生成 | 分析师、业务方 | 帮用户拆解问题和取数路径 | 计划看似完整但不可执行 |

## 游戏活动分析重点

游戏活动效果不能只看收入或参与率，应同时关注：

- 收入、付费率、ARPU（每用户平均收入）、ARPPU（每付费用户平均收入）
- 次日/七日留存、流失率、回流率
- 活动参与率、完成率、奖励领取率
- 新老用户、付费层级、渠道、区服、等级段等分群
- 活动前后对照、历史同类活动对照、同期版本/渠道干扰
- 护栏指标：短期收入提升是否牺牲长期留存或生态平衡

## 产品设计强信号

- 能区分“查数”“解释”“建议”“决策”的责任边界
- 输出中包含证据链、引用来源、口径说明和不确定性标注
- 能设计澄清问题，而不是让用户一次性说清所有上下文
- 能把失败场景转成产品机制：人工接管、改口径、重跑分析、结论分级
- 能用 MVP 先验证单一高频场景，而不是做万能分析助手

## 面试追问建议

1. 如果活动收入涨但留存跌，Agent 应先问用户哪些澄清问题？
2. 如果用户不信 Agent 的归因结论，产品上如何建立信任？
3. 如何防止 Agent 把相关性误判为因果？
4. 哪些分析结论必须人工确认？
5. 如何设计数据分析 Agent 的线上反馈和 bad case 回流？

## 评分锚点

| 分数 | 表现 |
|------|------|
| 5 分 | 能完整设计数据分析 Agent 的工作流、指标体系、人机协作、失败治理和迭代闭环 |
| 4 分 | 能设计可落地的数据分析 Agent 场景，并考虑口径、权限和解释性 |
| 3 分 | 能讲基本分析流程，但对游戏业务、归因和护栏指标理解一般 |
| 2 分 | 把数据分析理解为报表查询或自然语言 SQL |
| 1 分 | 缺少数据分析场景意识，无法说清用户和业务价值 |
