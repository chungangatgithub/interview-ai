## 一、多模态模型基础

### Q1.1 什么是多模态大模型 ⭐⭐

**问题**：
> 什么是多模态大模型（Multimodal LLM，多模态大语言模型）？它与纯文本 LLM 有什么区别？

**期望答案**：

**定义**：
多模态大模型是能够同时理解和处理多种模态信息（文本、图像、音频、视频等）的大语言模型。它将不同模态的信息统一映射到共享的语义空间中进行联合理解和推理。

**与纯文本 LLM 对比**：

| 维度 | 纯文本 LLM | 多模态 LLM |
|------|-----------|-----------|
| **输入模态** | 仅文本 | 文本 + 图像 + 音频 + 视频 |
| **输出模态** | 文本 | 文本（部分支持图像/音频生成） |
| **感知能力** | 仅语言理解 | 跨模态感知与推理 |
| **典型任务** | 问答、摘要、代码 | 图像描述、视觉问答、文档解析 |
| **架构复杂度** | Decoder-only | 视觉编码器 + 投影层 + LLM |

**核心能力**：
1. **视觉理解**：图像描述、OCR（光学字符识别）、图表解读
2. **跨模态推理**：根据图像内容回答文本问题
3. **文档解析**：PDF/表格/图表的结构化提取
4. **视频理解**：视频内容摘要、时间定位

**评分要点**：
- 3 分：知道多模态模型可以处理图像和文本
- 4 分：能说清与纯文本 LLM 的架构差异
- 5 分：能列举核心能力和典型应用场景

## 二、视觉语言模型架构

### Q2.1 VLM 架构演进 ⭐⭐⭐

**问题**：
> 视觉语言模型（VLM，Vision-Language Model）的主流架构有哪些？请解释"视觉编码器 + 连接模块 + LLM"的架构思路。

**期望答案**：

**主流架构模式**：

| 模式 | 代表模型 | 原理 | 优缺点 |
|------|---------|------|--------|
| **双塔对比学习** | CLIP、SigLIP | 图像和文本分别编码，对比学习对齐 | 适合检索，弱于生成 |
| **编码器-连接器-LLM** | LLaVA、Qwen-VL | 视觉编码器提取特征 → 投影层映射 → LLM 生成 | 主流方案，效果好 |
| **原生多模态** | GPT-4o、Gemini | 端到端训练，所有模态共享 Transformer | 效果最佳，训练成本极高 |

**"编码器-连接器-LLM"架构详解**：

```
图像输入 → Vision Encoder（视觉编码器，如 ViT）
                ↓
        视觉 Token 序列（如 576 个 Token）
                ↓
        Projection Layer（投影层/连接模块）
                ↓
        映射到 LLM 的 Embedding 空间
                ↓
        [视觉 Token] + [文本 Token] → LLM → 文本输出
```

**各组件说明**：

| 组件 | 作用 | 常见选择 |
|------|------|---------|
| **Vision Encoder（视觉编码器）** | 将图像提取为视觉特征 | ViT-L/14（CLIP）、SigLIP、InternViT |
| **Projection Layer（投影层）** | 将视觉特征对齐到语言空间 | MLP（线性投影）、Q-Former、Perceiver Resampler |
| **LLM** | 融合视觉和文本信息进行推理 | LLaMA、Qwen、Vicuna |

**连接模块对比**：

| 类型 | 代表 | 原理 | Token 数 |
|------|------|------|----------|
| **MLP 线性投影** | LLaVA | 简单线性映射 | 等于 ViT 输出（如 576） |
| **Q-Former** | BLIP-2 | 可学习的 Query 交叉注意力 | 固定（如 32） |
| **Perceiver Resampler** | Flamingo | 可学习的感知器压缩 | 固定（如 64） |

Q-Former 和 Perceiver Resampler 的优势是可以压缩视觉 Token 数量，减少 LLM 的计算开销。

**评分要点**：
- 3 分：知道 VLM 由视觉编码器和 LLM 组成
- 4 分：能解释投影层的作用和设计思路
- 5 分：能对比不同连接模块（MLP vs Q-Former）的优缺点

### Q2.2 图像分辨率处理策略 ⭐⭐⭐⭐

**问题**：
> 多模态模型如何处理不同分辨率的图像？高分辨率图像处理有哪些关键技术？

**期望答案**：

**核心挑战**：
- ViT 通常以固定分辨率训练（如 224×224 或 336×336）
- 实际输入图像分辨率差异巨大（从缩略图到 4K）
- Token 数量与分辨率的平方成正比：分辨率翻倍 → Token 数 4 倍 → 计算量激增

**主流处理策略**：

| 策略 | 代表模型 | 原理 | 优缺点 |
|------|---------|------|--------|
| **固定缩放** | 早期模型 | 统一缩放到固定尺寸 | 简单但损失细节 |
| **动态分块（Dynamic Tiling）** | LLaVA-NeXT、Qwen-VL | 将高分辨率图像切成多个子块分别编码 | 保留细节，Token 数可控 |
| **多尺度编码** | InternVL 2 | 不同分辨率提取不同层次特征 | 效果好，架构复杂 |
| **原生高分辨率** | GPT-4o | 内部自适应处理 | 效果最佳，实现未公开 |

**动态分块方案详解**（以 LLaVA-NeXT 为例）：
1. 输入高分辨率图像（如 1344×768）
2. 按预设网格切分为多个子块（如 2×3 = 6 个 336×336 块）
3. 额外缩放一个全局缩略图（336×336）保留全局信息
4. 每个子块分别经 ViT 编码
5. 拼接所有子块的视觉 Token + 全局 Token 输入 LLM

**Token 成本估算**（GPT-4o 为例）：
- 低分辨率模式：固定 85 Token
- 高分辨率模式：每个 512×512 块 ~170 Token，总计可达 1,105 Token
- 需权衡精度与成本

**评分要点**：
- 3 分：知道需要处理不同分辨率的图像
- 4 分：能解释动态分块的思路
- 5 分：能分析 Token 成本与精度的权衡策略

## 三、主流模型对比

### Q3.1 主流多模态模型对比 ⭐⭐⭐

**问题**：
> 当前主流的多模态大模型有哪些？请对比 GPT-4o、Claude、Gemini 的视觉能力差异。

**期望答案**：

**架构路线差异**：

| 模型 | 架构路线 | 核心特点 |
|------|---------|---------|
| **GPT-4o** | 统一 Dense Transformer（密集 Transformer），端到端多模态训练 | 所有模态通过相同的 Attention 机制处理，128K 上下文 |
| **Claude（Anthropic）** | Dense Transformer + Constitutional AI（宪法 AI） | 擅长文档分析、结构化视觉内容（PDF/图表/技术文档） |
| **Gemini（Google）** | 原生多模态架构，从头设计 | 支持文本/图像/音频/视频的同时处理，无需转换层 |
| **Qwen-VL（阿里）** | ViT + 动态分辨率 + Qwen LLM | 开源，中文能力强，支持多图理解 |
| **InternVL 2（上海 AI Lab）** | InternViT + 动态高分辨率 + InternLM | 开源最强之一，多语言多任务 |

**视觉能力侧重对比**：

| 能力维度 | GPT-4o | Claude | Gemini |
|---------|--------|--------|--------|
| **通用图像理解** | ★★★★★ | ★★★★ | ★★★★★ |
| **文档/PDF 解析** | ★★★★ | ★★★★★ | ★★★★ |
| **图表数据提取** | ★★★★ | ★★★★★ | ★★★★ |
| **实时视频理解** | ★★★★ | ★★★ | ★★★★★ |
| **音频理解** | ★★★★★ | ★★★ | ★★★★ |
| **代码截图理解** | ★★★★★ | ★★★★★ | ★★★★ |

**开源模型推荐**（2025-2026）：
- **通用视觉理解**：InternVL 2.5、Qwen2-VL
- **文档解析**：DocOwl、TextMonkey
- **轻量部署**：MiniCPM-V（端侧可部署）

**评分要点**：
- 3 分：知道主流多模态模型的名字
- 4 分：能说清各模型的架构差异和能力侧重
- 5 分：能结合具体场景推荐合适的模型

## 四、多模态应用实践

### Q4.1 多模态 RAG ⭐⭐⭐⭐

**问题**：
> 如何构建一个支持图文混合检索的多模态 RAG 系统？与纯文本 RAG 有何不同？

**期望答案**：

**多模态 RAG 架构**：

```
                 ┌─── 文本 → Text Embedding ───┐
文档（PDF/网页） ─┤                              ├→ 向量数据库 → Top-K → LLM
                 └─── 图表 → Vision Embedding ──┘
                                                         ↑
用户 Query ──→ Query Embedding ──────────────────────────┘
```

**与纯文本 RAG 的关键差异**：

| 维度 | 纯文本 RAG | 多模态 RAG |
|------|-----------|-----------|
| **文档解析** | 提取纯文本 | 需解析图片、表格、公式（OCR/文档解析模型） |
| **Embedding** | 单一文本 Embedding | 多模态 Embedding（如 CLIP）或分模态 Embedding |
| **分块策略** | 按段落/语句切分 | 需考虑图文关联性，保持图文上下文 |
| **检索** | 文本相似度 | 跨模态相似度检索 |
| **Prompt 构建** | 拼接文本片段 | 需构建图文混合 Prompt |

**核心技术选择**：

| 组件 | 方案选择 |
|------|---------|
| **文档解析** | Marker、Docling（PDF → Markdown + 图片提取） |
| **多模态 Embedding** | CLIP、BGE-M3（多模态版）、Jina CLIP v2 |
| **向量数据库** | Milvus（支持多向量字段）、Qdrant |
| **多模态 LLM** | GPT-4o、Claude、Qwen-VL |

**关键挑战与解法**：
1. **图文关联**：保留图片周围的标题/说明文字，作为图片的上下文元数据
2. **表格处理**：将表格转为 Markdown/HTML 文本，或用视觉模型直接理解表格截图
3. **跨模态对齐**：使用统一的多模态 Embedding（如 CLIP）将图文映射到同一空间

**评分要点**：
- 3 分：知道需要处理图像和文本两种模态
- 4 分：能说清多模态 RAG 与文本 RAG 的关键差异
- 5 分：能给出完整的技术方案选型

### Q4.2 视觉 Agent ⭐⭐⭐⭐⭐

**问题**：
> 什么是视觉 Agent（Vision Agent）？它是如何结合多模态感知和工具调用来完成复杂视觉任务的？

**期望答案**：

**定义**：
视觉 Agent 是结合多模态大模型的视觉理解能力和 Agent 工具调用能力的智能系统。它能"看"到图像/视频内容，理解用户意图，自主调用工具完成复杂的视觉任务。

**架构**：

```
视觉输入（截图/视频流）
        ↓
   VLM 感知与理解
        ↓
   任务规划与分解
        ↓
  ┌─────┼─────┐
  ↓     ↓     ↓
OCR   目标检测  代码执行   ← 工具调用
  ↓     ↓     ↓
  └─────┼─────┘
        ↓
   结果整合与输出
```

**典型应用场景**：

| 场景 | 描述 | 示例 |
|------|------|------|
| **GUI 自动化** | 理解屏幕截图，模拟鼠标/键盘操作 | 自动填写表单、操作应用 |
| **文档智能处理** | 理解复杂文档布局，提取结构化信息 | 发票识别、合同审查 |
| **视觉质检** | 分析产品图片，检测缺陷 | 工业质检、医学影像 |
| **网页自动化** | 理解网页内容和布局，执行操作 | 自动化测试、数据采集 |

**关键技术**：
1. **Grounding（定位）**：将自然语言描述映射到图像中的具体区域/坐标
2. **Set-of-Mark（标记集）**：在截图上标注可交互元素的编号，让 VLM 通过编号引用
3. **GUI 坐标预测**：VLM 直接输出点击坐标（如 "click(0.5, 0.3)"）
4. **反思与纠错**：执行后截图验证结果，失败时自动调整策略

**代表性框架**：
- **OpenAI Computer Use**（概念）：GPT-4o + 屏幕截图 + 鼠标键盘操作
- **Anthropic Computer Use**：Claude + 屏幕感知 + 工具调用
- **CogAgent**：智谱 AI 开源，专注 GUI 理解和操作
- **SeeClick**：基于 Set-of-Mark 的 GUI Agent

**评分要点**：
- 3 分：知道视觉 Agent 可以理解图像并执行操作
- 4 分：能描述 VLM + 工具调用的架构
- 5 分：能讲解 Grounding/Set-of-Mark 等关键技术
