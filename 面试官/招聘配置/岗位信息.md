# 岗位信息

**当前招聘岗位**：AI 产品经理（数据分析智能体方向）

---

## 岗位定位

该岗位不是传统 BI 产品经理，也不是纯算法 / 工程岗位，而是面向 **数据分析智能体系统** 的 AI 原生产品经理。核心任务是把 LLM、Agent、RAG、多模态、人机协作等 AI 能力，转化为数据分析师、业务策划、运营等角色可持续使用的产品能力。

重点关注候选人是否能同时理解：

- **业务场景**：数据分析师、业务策划、游戏运营等用户如何提出问题、拆解指标、验证假设、产出结论
- **AI 产品能力边界**：哪些环节适合 Agent 自动化，哪些环节必须保留人类判断、确认和追责
- **产品创新方法**：能否从 0 到 1 探索 AI Agent 在数据分析领域的新范式，而不是简单把 ChatBot 套到 BI 上
- **交付落地能力**：能否定义清晰 PRD、协调技术与业务团队、通过实验和反馈持续迭代

## 核心要求与判断依据

### 1. AI 产品认知

**要求**：对 ChatGPT、Claude、Perplexity、Cursor、Devin、Manus、各类数据分析 Agent 等前沿 AI 产品保持高频使用和跟踪，能说清楚其能力边界、交互范式和产品取舍。

**强信号**：

- 能结合具体产品拆解 AI 交互范式，而不是停留在"我用过很多 AI 工具"
- 能说明 Agent 相比传统 Copilot / ChatBot 的差异：任务拆解、工具调用、上下文管理、记忆、验证、可追溯性
- 能识别 AI 产品的典型问题：幻觉、不可控、结果不可解释、上下文污染、评估困难、用户信任不足
- 有自己的 AI 产品观察和判断，能输出清晰观点

**弱信号 / 风险**：

- 只把 AI 当作提效工具，不理解 AI 原生产品形态
- 过度相信 AI 自动化，缺少边界意识和失败兜底设计
- 只能复述行业热词，无法落到具体用户价值和产品机制

### 2. 数据分析场景理解

**要求**：理解数据分析流程、A/B 测试原理、指标体系、归因分析和业务决策链路，能围绕数据分析师与业务策划的真实工作流设计智能化解决方案。

**强信号**：

- 能描述从业务问题到分析结论的完整链路：问题定义、指标拆解、取数、清洗、分析、可视化、解释、建议、复盘
- 理解 A/B 测试的关键要素：假设、实验分组、样本量、显著性、指标选择、实验污染、长期效果
- 能区分"帮用户查数"、"帮用户分析"、"帮用户形成决策建议"之间的产品边界
- 能设计人机协作流程，让 AI 负责高频、机械、探索性工作，让人负责目标、判断、确认和责任承担

**弱信号 / 风险**：

- 把数据分析理解为报表查询或自然语言生成 SQL
- 不重视数据口径、指标定义、权限、审计、可解释性
- 对业务策划 / 分析师的实际工作流缺少感知

### 3. Agent 产品设计能力

**要求**：能探索 AI Agent 在数据分析领域的创新应用场景，并把抽象 AI 能力转化为可定义、可交付、可评估的产品功能。

**强信号**：

- 能提出具体 Agent 场景，例如：自动分析异常波动、辅助拆解活动效果、生成分析计划、跨表取数与解释、自动形成复盘报告
- 能设计 Agent 工作流：输入、意图识别、任务规划、工具调用、结果验证、中间态展示、人工确认、反馈学习
- 能考虑产品体验细节：如何让用户知道 Agent 做到哪一步、为什么这么做、哪里需要用户确认
- 能从失败场景倒推产品机制，例如置信度、引用来源、可回滚、人工接管、结论分级

**弱信号 / 风险**：

- 只描述"做一个数据分析 Agent"，无法拆成可落地功能
- 只关注大模型能力，不关注工具、数据、权限、评估、用户信任
- PRD 只写功能列表，缺少用户目标、场景闭环和验收标准

### 4. B 端产品与交付能力

**要求**：具备 3 年以上 B 端产品经验，能定义需求、编写 PRD、推动跨团队协作，并保证产品交付质量。

**强信号**：

- 能清楚讲出自己负责过的 B 端产品模块、目标用户、关键指标、上线过程和迭代结果
- 能平衡业务诉求、技术约束、数据安全、交付周期和长期产品架构
- 能用 MVP、灰度、实验、用户访谈、数据反馈来验证产品假设
- 能推动技术、算法、数据、业务、运营等多角色协作

**弱信号 / 风险**：

- 只有项目管理经验，缺少产品定义和取舍能力
- 只会承接需求，不会重构问题和识别真正用户价值
- 对复杂 B 端系统中的权限、配置、口径、流程、组织协同缺少敏感度

### 5. 创新与学习能力

**要求**：开放、好奇，能快速吸收海外 AI 产品资料和研究报告，能主动建立产品实验文化，通过快速迭代验证想法。

**强信号**：

- 长期跟踪 AI 产品社区、Agent / RAG / 多模态等方向，并能形成自己的产品洞察
- 有从 0 到 1 打造创新产品的经验，能讲清楚不确定性、探索路径和关键转折点
- 能接受 AI 产品早期的不完美，并知道如何通过实验、评估和反馈逼近可用
- 有技术背景或足够技术理解力，能与工程团队讨论方案边界和实现成本

**弱信号 / 风险**：

- 只追热点，缺少结构化学习和判断框架
- 不愿意面对不确定性，习惯用传统产品框架套 AI 产品
- 无法解释自己如何判断一个 AI 产品想法是否值得投入

## 方向匹配判断指引（供 `/qa` 命令使用）

模型在生成问答时，**自行判断候选人方向与岗位需求、面试官方向的匹配度**，按以下原则决定考察策略：

- **高度匹配**（AI 产品经理 / Agent 产品 / 数据产品 / BI 产品 / AI 数据分析产品）→ 深挖 AI 产品判断、数据分析场景、Agent 设计、PRD 取舍、落地复盘
- **较匹配**（B 端产品经理，有数据、游戏、工具、平台、编辑器或 AI 工具经验）→ 重点考察场景理解、产品抽象、用户研究、跨团队推进；AI 深度用产品认知题校准
- **部分匹配**（游戏策划 / 业务策划 / 数据分析师转产品，或 AI 重度使用者但产品经验不足）→ 重点判断业务理解、结构化思考、AI 产品潜力和 0 到 1 学习能力
- **方向偏差**（纯算法 / 纯开发 / 纯数据工程 / 传统项目经理）→ 少考执行细节，多考用户价值、产品意识、AI 能力边界和协作判断；技术细节明确"不是本轮主考重点"
- **明显不匹配**（只会传统报表、无 AI 热情、无 B 端产品经验、缺少数据分析理解）→ 重点验证是否存在基本岗位门槛，不必深入追问高级 Agent 设计

## 面试追问建议

- 让候选人选一个熟悉的 AI 产品，拆解其用户场景、核心交互、能力边界和可改进点
- 让候选人设计一个"数据分析 Agent 帮游戏策划分析活动效果"的完整方案
- 追问候选人如何处理 AI 分析结果不准确、用户不信任、数据口径不一致的问题
- 让候选人讲一个从 0 到 1 或不确定性较高的产品探索经历，看其如何验证假设和做取舍
- 对有游戏经验的候选人，重点追问活动分析、留存、付费、关卡 / 系统调优、玩家分群等场景
- 对有技术背景的候选人，可追问 Agent 架构边界、工具调用、RAG、评估体系和工程协作，但不要求算法级实现细节

详细规则见 `.claude/commands/AI产品问答生成.md` 或 `.cursor/commands/AI产品问答生成.md` 中「方向选择规则」段。
